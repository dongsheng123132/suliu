GET/api/holdings

攻击者控制过的全部地址，按链分组，含已转空的地址，名单只增不减，可直接用于拉黑。链内当前有余额的排前面（按余额降序），已转空的排后面。免登录、免 key，允许跨域。

Every address the attacker has controlled, grouped by chain, including addresses that have since been emptied. The list only grows, so it can be used as a blocklist. Within each chain, addresses that still hold funds come first (by balance, descending), followed by emptied ones. No sign-in or API key; CORS open.

  "xrp": ["r6NcwN3dR5ciyBv9XsLyMNc9Kg2FBCs7Y", …],
  "btc": ["bc1q…", …],
  …
}
  • 链：eth bsc arb op base avax linea xrp btc tron zec algo tia atom noble hyperliquid sol；EVM 地址为小写（hyperliquid 是 Hyperliquid 账户，地址格式同 EVM）。
  • 地址转空后仍留在名单里，不代表解除；经核实不属于攻击者的地址会移除。
  • 缓存 5 秒，建议 15–30 秒拉一次；数据时间见响应头 x-snap-ts（Unix 秒）。
  • 请带自定义 User-Agent，Python 等默认 UA 会被拦（403）。
  • Chains: eth bsc arb op base avax linea xrp btc tron zec algo tia atom noble hyperliquid sol; EVM addresses are lower-case (hyperliquid lists Hyperliquid accounts, which use EVM-format addresses).

  • Cached for 5 s; polling every 15–30 s is enough. Data time is in the x-snap-ts header (Unix seconds).
  • Send a custom User-Agent; default library UAs such as Python's are blocked (403).

GET/api/chains

  
每条链上攻击者资金的累计流入 / 流出 / 内部调动（地址浏览器选中一条链时表格上方那一条的数据来源）：按交易缓存里攻击者地址在这条链上的全部转账累计，流入 = 非攻击者地址转给攻击者地址（不含我方被盗钱包的初始转入），流出 = 攻击者地址转给非攻击者地址，内部 = 攻击者地址之间。兑换在同一条链上先流出再流入、两头都算；同一笔钱经过几条链会在每条链各算一次，各链的数不能相加。免登录、免 key，允许跨域。

  
Cumulative inflow / outflow / internal moves of attacker funds on each chain (what the summary bar above the address explorer table shows when a chain is selected): every cached transfer of attacker addresses on that chain, where inflow = non-attacker → attacker (excluding the initial transfers out of our victim wallets), outflow = attacker → non-attacker, internal = attacker → attacker. A swap on one chain counts on both sides (out, then back in); money that crosses several chains is counted once per chain, so chains must not be added up. No sign-in or API key; CORS open.


  
请求Request

  
curl -s -A 'my-client/1.0' https://trace.bgblockchain.xyz/api/chains


  
返回Response

  
{
  "ok": true,
  "generated_ts": 1790535200,
  "method": "…",
  "items": [
    { "chain": "NOBLE", "in_usd": 7137365.2, "out_usd": 7110624.0, "internal_usd": 6406169.0,
      "n_in": 46, "n_out": 66, "n_internal": 29, "unpriced": 0, "t0": 1790496620, "t1": 1790533550 },
    …
  ]
}


  
    
    
  • items 按 流入 + 流出 从大到小；n_* 是笔数，unpriced 是没能折算成美元、只计了笔数的转账条数，t0 / t1 是这条链上最早 / 最近一笔的时间（Unix 秒）。
    • 
    
  • 交易缓存比链上晚 1–10 分钟（EVM 1–2 分钟，其余链最多 10 分钟）；缓存约 5 分钟，User-Agent 要求同 /api/holdings。
    • 
  

  
    
    
  • items are sorted by inflow + outflow, descending; n_* are transfer counts, unpriced is the number of transfers that could not be valued in USD (counted only), t0 / t1 are the earliest / latest transfer on that chain (Unix seconds).
    • 
    
  • The transaction cache lags the chain by 1–10 minutes (1–2 on EVM chains, up to 10 elsewhere); cached for about 5 minutes; the User-Agent rule is the same as for /api/holdings.
    • 
  


  

  






  
GET/api/maintenance

  
维护状态。看板修复期间会打开维护开关，两种模式：block：页面和数据接口返回 503（响应头 retry-after 是建议的重试秒数），请沿用上次拉取的名单，不要当成空列表；freeze：接口照常返回，但数据停在冻结那一刻的快照（响应头 x-maintenance: freeze，x-snap-ts 是那份快照的时间），恢复后自动更新。免登录、免 key，允许跨域。

  
Maintenance status. While the dashboard is being repaired a maintenance switch is on, in one of two modes. block: pages and data endpoints return 503 (the retry-after header is the suggested wait in seconds); keep the list you last fetched, do not treat it as empty. freeze: endpoints keep answering, but the data stays at the snapshot taken when the freeze began (x-maintenance: freeze header; x-snap-ts is that snapshot's time) and updates again once restored. No login or key, CORS enabled.


  
请求Request

  
curl -s -A 'my-client/1.0' https://trace.bgblockchain.xyz/api/maintenance


  
返回Response

  
{"ok": true, "on": false, "mode": null, "since": null, "frozen_ts": null, "msg_zh": "", "msg_en": ""}

{"ok": true, "on": true, "mode": "freeze", "since": 1790560000, "frozen_ts": 1790559900,
 "msg_zh": "数据核对中", "msg_en": "Data being verified"}

  
    
    
  • on 开关是否打开；mode block / freeze（关着时为 null）；since 打开时间（Unix 秒）；frozen_ts freeze 时对外那份快照的时间；msg_zh / msg_en 说明。
    • 
  

  
    
    
  • on whether the switch is on; mode block / freeze (null when off); since when it was turned on (Unix seconds); frozen_ts the time of the snapshot being served during a freeze; msg_zh / msg_en a note.

POST/api/report

  
向 Bitget 安全团队提交线索，效果和 /report 页面提交一样：进入线索库，由安全团队逐条核实，返回线索编号。免登录、免 key。支持 JSON（不带附件）和 multipart/form-data（可带图片附件）。

  
Send a lead to the Bitget security team. It is handled exactly like a submission on the /report page: stored in the lead database for the security team to review, and a lead reference is returned. No sign-in or API key. Accepts JSON (no attachments) or multipart/form-data (with image attachments).


  
请求（JSON）Request (JSON)

  
curl -s -A 'my-client/1.0' https://trace.bgblockchain.xyz/api/report \
  -H 'content-type: application/json' \
  -d '{"contact": "whitehat@example.com", "kind": "funds", "dest": "cex",
       "chain": "Bitcoin", "address": "bc1q…", "amount": "3.99", "token": "BTC",
       "txs": ["0a2468…", "c6a74b…"], "desc": "…"}'


  
请求（带附件）Request (with attachments)

  
curl -s -A 'my-client/1.0' https://trace.bgblockchain.xyz/api/report \
  -F contact=whitehat@example.com -F chain=Bitcoin -F address=bc1q… -F desc='…' \
  -F files=@screenshot1.png -F files=@screenshot2.jpg


  
返回Response

  
{
  "ok": true,
  "id": "260926-201530-ABCD",
  "ts": "2026-09-26T12:15:30.123Z",
  "bj": "2026-09-26 20:15:30"
}


  
    
    
  • 必填 contact：联系方式（邮箱 / Telegram 等），只用于核实和发放奖励，不公开。填邮箱的话，之后可以用 /api/report/mine 查到。
    • 
    
  • 至少填一项：address 目的地址（≤ 300 字）、txs 交易哈希（每行一个或 JSON 数组，≤ 10,000 字）、desc 描述（≤ 10,000 字）。
    • 
    
  • 选填：kind 类型 funds / identity / method / other（默认 other）；dest 资金去向 cex / bridge / dex / otc / mixer / other；chain 链（如 Bitcoin、XRP Ledger、Ethereum）；amount、token 金额和币种；alias 称呼；lang zh / en。
    • 
    
  • files 附件（只在 multipart 里）：最多 3 张，每张 ≤ 2 MB，只收 PNG / JPG / WEBP（按文件内容识别）。
    • 
    
  • 文字字段（desc、txs 等）要作为普通表单字段发送，不要当文件上传；内容是「[object File]」之类的会被拒收（bad_field / field_is_file），不会存。
    • 
    
  • 失败返回 {"ok": false, "error": "…"}：400 missing_contact / missing_content / too_long（detail 是超长的字段）/ too_many_files / file_too_large / bad_file / bad_json；413 请求体过大；415 不支持的 Content-Type；429 rate_limited。
    • 
    
  • 不支持跨域，请从服务端或命令行调用。同一条线索请不要重复提交；需要补充时再提交一条，在 desc 里写上原编号。
    • 
  

  
    
    
  • Required contact: how to reach you (email / Telegram etc.), used only to verify the lead and pay rewards, never published. If it is an email, you can later find the lead with /api/report/mine.
    • 
    
  • At least one of: address destination address (≤ 300 chars), txs transaction hashes (one per line or a JSON array, ≤ 10,000 chars), desc description (≤ 10,000 chars).
    • 
    
  • Optional: kind funds / identity / method / other (default other); dest fund destination cex / bridge / dex / otc / mixer / other; chain (e.g. Bitcoin, XRP Ledger, Ethereum); amount, token; alias your name; lang zh / en.
    • 
    
  • files attachments (multipart only): up to 3 images, 2 MB each, PNG / JPG / WEBP only (checked by file content).
    • 
    
  • Text fields (desc, txs, …) must be sent as plain form fields, not file uploads. Values like "[object File]" are rejected (bad_field / field_is_file) and nothing is stored.
    • 
    
  • Errors return {"ok": false, "error": "…"}: 400 missing_contact / missing_content / too_long (detail names the field) / too_many_files / file_too_large / bad_file / bad_json; 413 body too large; 415 unsupported Content-Type; 429 rate_limited.
    • 
    
  • No CORS: call it from a server or the command line. Please don't submit the same lead twice; to add details, submit again and quote the original reference in desc.
    • 
  






  
GET/api/report/mine?c=

  
按联系方式查询在 /report 提交过的线索。c 填提交时写的邮箱（或联系方式原文），不区分大小写。为保护隐私，只返回编号、提交时间、类型、链和打码后的地址，邮箱和地址只显示前后几位；不返回描述、金额和核查结果。免登录、免 key。

  
Look up leads submitted through /report by contact. Set c to the email (or the exact contact) given when submitting; case-insensitive. For privacy, only the reference, submission time, type, chain and a partly hidden address are returned, and the email is partly hidden too; descriptions, amounts and review results are never returned. No sign-in or API key.

  • 所有接口都要带自定义 User-Agent，Python 等默认 UA 会被拦（403）。
